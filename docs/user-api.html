Base & Auth

Base URL
https://events-api-production-138b.up.railway.app/api
Auth header
Authorization: Bearer {token}
Content-Type
application/json — except image uploads → multipart/form-data
Accept
application/json (always send this header)
Language
Accept-Language: ar أو en (يُرسَل مع كل طلب)
كل الـ endpoints تحتاج الـ Authorization: Bearer {token} ما عدا تسجيل الدخول (send-otp / verify-otp / complete-registration) وشاشات التصفّح العامة (GET /vendors، GET /products، صفحة أي vendor وتقييماته ومعرضه وتقويمه). الـ token بتاخذه من الـ login. للتجربة الحالية: الـ otp برجع جوّا الـ response مباشرة، فما بتحتاج WhatsApp. أي طلب فيه رفع صورة (صورة البروفايل) لازم يكون multipart/form-data، والباقي JSON.
Localization: أرسل Accept-Language: ar أو en مع كل طلب — الرسائل ونصوص الأخطاء (message / errors) ترجع باللغة المطلوبة. أما قيم الـ enum (مثل vendor_type، status، booking_style) فترجع دائماً بمفاتيح إنجليزية ثابتة — التطبيق هو اللي بيحوّلها لتسميات عربية عند العرض.

Common Responses — ردود مشتركة

هي الردود ممكن ترجع من أي endpoint، فمذكورة هون مرّة وحدة بدل ما تتكرر بكل نقطة. تحت كل endpoint بنذكر بس الردود الخاصة فيه. كل الردود JSON. النجاح غالباً فيه "status": "success"، والخطأ فيه "status": "error" و "message".
401Unauthenticated — التوكن ناقص أو غير صالح (على أي endpoint محمي). أرسل دائماً Accept: application/json وإلا بيرجع redirect.
"message": "Unauthenticated."
403Account suspended — الحساب محظور من الأدمن (is_active = false). middleware الـ active بيمنع أي endpoint محمي.
{
  "status": "suspended",
  "message": "Your account has been suspended. Please contact support."
}
422Validation error — حقل ناقص أو غير صحيح. errors فيه رسالة لكل حقل. (مثال عام).
{
  "message": "The phone field is required.",
  "errors": {
    "phone": ["The phone field is required."]
  }
}

1 · Authentication — تسجيل الدخول والتسجيل

POST/send-otp🌐 Public
Job
يرسل رمز تحقق (OTP) لرقم الموبايل عبر WhatsApp. للتجربة الرمز برجع جوّا الـ response بحقل otp.
Body
FieldTypeRequiredالشرح
phonestringrequiredرقم الموبايل، أرقام فقط مع إمكانية + (7–15 خانة).
Responses
200تم الإرسال. otp يظهر للتجربة فقط. ultramsg_status=404 يعني اشتراك WhatsApp موقوف حالياً (طبيعي بالتجربة).
{
  "message": "OTP sent",
  "otp": 834192,
  "ultramsg_status": 404,
  "ultramsg_response": { /* رد WhatsApp */ }
}
422رقم غير صالح (فاضي، أحرف، أو خارج 7–15 خانة).
{ "message": "The phone field is required.", "errors": { "phone": [ "..." ] } }
POST/verify-otp🌐 Public
Job
يتحقق من الـ OTP. إذا الرقم موجود مسبقاً → بيرجّع status: login مع token وبيانات الـ user. إذا جديد → بيرجّع status: new_user مع registration_token لإكمال التسجيل.
Body
FieldTypeRequiredالشرح
phonestringrequiredنفس الرقم المُرسل له الـ OTP.
otpintegerrequiredالرمز المكوّن من 6 أرقام.
Responses
200الرقم موجود مسبقاً — تسجيل دخول. يرجّع token وكامل بيانات الـ user.
{
  "status": "login",
  "token": "45|aBcD3fGhIjKlMnOpQrStUvWxYz...",
  "user": {
    "id": 88,
    "first_name": "Lana",
    "last_name": "Khaled",
    "phone": "+963955112233",
    "city": "Damascus",
    "birth_date": "2000-06-01T00:00:00.000000Z",
    "latitude": null,
    "longitude": null,
    "address": null,
    "is_active": true,
    "profile_image_url": null
    /* ... created_at / updated_at. fcm_token و remember_token غير موجودين أبداً */
  }
}
200رقم جديد — يرجّع registration_token (صالح 15 دقيقة) لإكمال التسجيل.
{
  "status": "new_user",
  "registration_token": "a1b2c3...64chars"
}
400الـ OTP خاطئ أو منتهي الصلاحية.
{ "message": "Invalid OTP" }

4 · Bookings & Orders — الحجوزات والطلبات

حالات الحجز (status): awaiting_payment مسوّدة بانتظار الدفع · pending مدفوع وبانتظار موافقة الـ vendor · approved تمت الموافقة · completed منتهٍ · declined مرفوض · cancelled ملغى

شكلان للحجز — الخادم يقرّر أيّهما حسب booking_style تبع الـ vendor (لا ترسله أنت):
• appointment (مزوّدو الخدمات): vendor_product_id + event_date (مطلوب ومستقبلي) + اختياري event_location/duration_hours/selected_options. حقول الطلب ممنوعة.
• order (المتاجر): items:[{vendor_product_id, quantity, selected_options}] — مصفوفة items[] هي الشكل الوحيد حتى لو منتج واحد + اختياري delivery_date/delivery_address. حقول الموعد ممنوعة.
الشكل الخطأ → 422. selected_options = JSON حرّ يختاره العميل من meta المنتج (لون، حجم...). نفس المنتج بخيارات مختلفة = سطر منفصل في السلة.

5 · Payments — الدفع

التطبيق يرسل فقط booking_id + transaction_id — لا يرسل المبلغ، الخادم يحسبه:
• Appointment = عربون 20% من السعر (بعد الخصم إن وُجد).
• Order = إجمالي السلة كاملاً.
العمولة دائماً 15% من السعر الأصلي. بعد نجاح الدفع تتحوّل حالة الحجز من awaiting_payment إلى pending.
transaction_id = "0000" هو bypass للتجربة (يتخطّى ShamCash ويمكن إعادة استخدامه).

Job
يتحقق من دفعة ويؤكّد الحجز. المبلغ المتوقّع يحسبه الخادم. عند النجاح: تُنشأ الدفعة وتتحوّل الحالة إلى pending ويُشعَر الـ vendor.

Responses

10 · Support Tickets — تذاكر الدعم

العميل يفتح تذاكر. فتح تذكرة = موضوع + أول رسالة (+ حجز اختياري + فئة). لا يمكن للعميل المتابعة بالكتابة إلا بعد أن يرد الدعم (تصبح محادثة). التذكرة resolved تبقى مغلقة — مشكلة جديدة = تذكرة جديدة.
حالات التذكرة: open (بانتظار رد الدعم) · replied (رد الدعم — يمكنك الكتابة) · resolved (مغلقة).
