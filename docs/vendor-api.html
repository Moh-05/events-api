Vendor App API Reference

دليل نقاط الـ API الخاصة بتطبيق الـ Vendor — Flutter Team Reference · v2.0 · June 2026

Base Configuration

Base URL https://events-api-production-138b.up.railway.app/api
Auth Header Authorization: Bearer {token}
Accept Header Accept: application/json
File Uploads Content-Type: multipart/form-data — required when sending images
🔒 Token required — Bearer token returned by verify-otp or complete-registration. Store it on device after login.
🌐 Public — No auth header needed for these endpoints.
Note: currently in testing mode, otp is returned in the send-otp response for easier testing. Remove before production.

المصادقة

Auth
POST /vendor/send-otp 🌐 Public
يُرسل رمز OTP عبر WhatsApp إلى رقم الهاتف — أول خطوة في تسجيل الدخول أو إنشاء حساب جديد.
FieldTypeStatusشرح
phonestringrequiredرقم الهاتف بالصيغة الدولية (مثال: +963911...)
POST /vendor/verify-otp 🌐 Public
يتحقق من رمز OTP — إذا كان الـ vendor مسجّلاً سابقاً يُعيد token مباشرةً (حالة login)، وإن كان جديداً يُعيد registration_token مؤقتاً لإتمام التسجيل (حالة new_vendor).
FieldTypeStatusشرح
phonestringrequiredنفس الرقم المُستخدم في send-otp
otpintegerrequiredالرمز المكوّن من 6 أرقام المُرسَل عبر WhatsApp
POST /vendor/complete-registration 🌐 Public
يُكمل تسجيل vendor جديد — يُستدعى فقط عند status: new_vendor. يُنشئ الحساب ويُعيد الـ Bearer token مباشرةً.
FieldTypeStatusشرح
registration_tokenstring (64)requiredالتوكن المؤقت من verify-otp (صالح 15 دقيقة)
first_namestringrequiredالاسم الأول
last_namestringrequiredالاسم الأخير
citystringrequiredالمدينة
birth_datedaterequiredتاريخ الميلاد (YYYY-MM-DD)

الملف الشخصي

Profile
GET /vendor/profile 🔒 Token
يُرجع بيانات الـ vendor الحالي كاملةً — الاسم، نوع الخدمة، المدينة، الموقع الجغرافي، حالة الموافقة، متوسط التقييم.
لا يحتاج body
POST /vendor/profile/type 🔒 Token
يُحدد نوع نشاط الـ vendor — يجب استدعاؤها مرة واحدة قبل إنشاء المنتجات أو استقبال الحجوزات. تُعيّن booking_style تلقائياً: المحلات والمتاجر = order، القاعات والمصورين والـ DJ = appointment.
FieldTypeStatusشرح
vendor_typeenumrequiredwedding_venue · photographer · dj · cake_shop · store
POST /vendor/profile 🔒 Token
يُحدّث بيانات الملف الشخصي — جميع الحقول اختيارية، يمكن إرسال أي حقل بمفرده. إذا أُرسلت صورة يجب استخدام multipart/form-data.
FieldTypeStatusشرح
business_namestringoptionalاسم النشاط التجاري
biostringoptionalنبذة تعريفية (max 1000 حرف)
birth_datedateoptionalتاريخ الميلاد (YYYY-MM-DD)
latitudedecimaloptionalخط العرض (-90 to 90)
longitudedecimaloptionalخط الطول (-180 to 180)
addressstringoptionalالعنوان بالنص (max 255 حرف)
profile_imagefileoptionalصورة الملف الشخصي — jpg/jpeg/png · max 2 MB
DELETE /vendor/profile/image 🔒 Token
يحذف صورة الملف الشخصي من الخادم ويُفرّغ الحقل في قاعدة البيانات.
لا يحتاج body
POST /vendor/fcm-token 🔒 Token
يحفظ FCM device token للـ vendor — يُستدعى عند كل تسجيل دخول لضمان وصول الإشعارات للجهاز الحالي. الـ FCM token يختلف تماماً عن Sanctum token.
FieldTypeStatusشرح
fcm_tokenstringrequiredتوكن الجهاز من Firebase SDK (يختلف لكل جهاز)

المنتجات والخدمات

Products
GET /vendor/products 🔒 Token
يُرجع جميع منتجات/خدمات الـ vendor الحالي المتاحة (is_available = true) مع صورها.
لا يحتاج body
POST /vendor/products 🔒 Token
يُنشئ منتجاً/خدمة جديدة — الصور إجبارية (images[])، بقية الحقول اختيارية. يجب إرسال الطلب بـ multipart/form-data.
FieldTypeStatusشرح
images[]file[]requiredصور المنتج — jpg/jpeg/png · max 2 MB لكل صورة
namestringoptionalاسم المنتج أو الخدمة
descriptionstringoptionalوصف تفصيلي
pricedecimaloptionalالسعر الكامل بالليرة السورية
stockintegeroptionalالكمية المتوفرة (للمحلات التي تتتبع المخزون فقط)
metaobjectoptionalبيانات JSON مرنة خاصة بالنوع (مواصفات، ألوان...)
primary_image_indexintegeroptionalرقم الصورة الرئيسية في المصفوفة (0-based، default: 0)
GET /vendor/products/best-sellers 🔒 Token
يُرجع أفضل 5 منتجات بحسب عدد الطلبات والحجوزات المدفوعة — مخصص لبطاقة "الأكثر طلباً" في لوحة تحكم المحلات.
لا يحتاج body
GET /vendor/products/low-stock 🔒 Token
يُرجع المنتجات التي وصل مخزونها لحد التنبيه أو أقل — لتنبيهات المخزون في لوحة تحكم المحلات. يتجاهل المنتجات التي لا تتتبع مخزوناً.
FieldTypeStatusشرح
thresholdintegerquery paramحد التنبيه (default: 5) — مثال: ?threshold=10
GET /vendor/products/{id} 🔒 Token
يُرجع تفاصيل منتج واحد مع صوره الكاملة — الـ vendor يرى منتجاته الخاصة فقط.
لا يحتاج body
POST /vendor/products/{id} 🔒 Token
يُحدّث بيانات منتج ويُدير صوره — يُستخدم POST بدلاً من PATCH/PUT لأن PHP على Railway لا يقرأ multipart/form-data مع PUT/PATCH. جميع الحقول اختيارية.
FieldTypeStatusشرح
namestringoptionalاسم جديد للمنتج
descriptionstringoptionalوصف جديد
pricedecimaloptionalسعر جديد
stockintegeroptionalكمية جديدة في المخزون
metaobjectoptionalبيانات JSON جديدة
images[]file[]optionalصور جديدة لإضافتها
primary_image_indexintegeroptionalرقم الصورة الرئيسية من بين الصور الجديدة المرسلة
delete_image_ids[]integer[]optionalIDs الصور القديمة المراد حذفها
DELETE /vendor/products/{id} 🔒 Token
يحذف المنتج وجميع صوره من الخادم وقاعدة البيانات بشكل نهائي.
لا يحتاج body

الحجوزات والطلبات

Bookings
Booking Status Flow (Pay-First):
awaiting_payment → [customer pays] → pending → [vendor approves] → approved → [event/delivery done] → completed
awaiting_payment → cancelled (customer cancels before paying)  |  pending → declined (vendor declines)
GET /vendor/bookings 🔒 Token
يُرجع جميع حجوزات الـ vendor مرتبةً من الأحدث — يُستخدم لعرض القائمة الكاملة في لوحة التحكم.
لا يحتاج body
GET /vendor/bookings/recent-requests 🔒 Token
يُرجع أحدث 10 حجوزات بحالة pending تنتظر قرار القبول أو الرفض — مخصص لبطاقة "الطلبات الجديدة" في الـ dashboard. (pending = دُفع ومنتظر موافقة الـ vendor)
لا يحتاج body
GET /vendor/bookings/recent-orders 🔒 Token
يُرجع أحدث 10 طلبات للمحلات (cake_shop, store) — يستثني الطلبات غير المدفوعة. لـ appointment vendors يُعيد قائمة فارغة.
لا يحتاج body
GET /vendor/bookings/upcoming-events 🔒 Token
يُرجع الحجوزات المقبولة (approved) ذات تاريخ مستقبلي مرتبةً تصاعدياً — مخصص لـ vendors من نوع appointment (قاعات، مصورين، DJ).
لا يحتاج body
GET /vendor/bookings/{id} 🔒 Token
يُرجع تفاصيل حجز واحد كاملةً — يشمل بيانات المستخدم، صور المنتج، ومعلومات الدفعة.
لا يحتاج body
POST /vendor/bookings/{id}/approve 🔒 Token
يقبل الـ vendor الحجز — يُغيّر حالته من pending إلى approved. يعمل فقط على الحجوزات المدفوعة (حالة pending).
لا يحتاج body
POST /vendor/bookings/{id}/decline 🔒 Token
يرفض الـ vendor الحجز — يُغيّر حالته من pending إلى declined.
لا يحتاج body
POST /vendor/bookings/{id}/complete 🔒 Token
يُغلق الحجز كمُكتمل — يُستدعى يوم الفعالية أو بعد تسليم الطلب. يُغيّر الحالة من approved إلى completed فقط.
لا يحتاج body
GET /vendor/booked-dates 🔒 Token
يُرجع قائمة التواريخ المحجوزة — يُستخدم لتظليل الأيام غير المتاحة في التقويم (appointment vendors فقط). يشمل الحجوزات بحالة pending أو approved.
لا يحتاج body

التقييمات

Reviews
GET /vendor/reviews 🔒 Token
يُرجع جميع تقييمات الـ vendor الحالي مع بيانات المستخدم ومتوسط التقييم العام.
لا يحتاج body
GET /vendor/reviews/summary 🔒 Token
يُرجع ملخصاً تفصيلياً للتقييمات — توزيع النجوم من 1 إلى 5، نسبة التقييمات الإيجابية، مقارنة مع الشهر الماضي.
لا يحتاج body

الإحصائيات والأرباح

Stats & Earnings
GET /vendor/stats 🔒 Token
يُرجع إحصائيات شاملة — عدد الحجوزات مُصنَّفةً حسب الحالة (pending / approved / completed / declined / cancelled)، إجمالي الأرباح، متوسط التقييم، عدد التقييمات.
لا يحتاج body
GET /vendor/earnings 🔒 Token
يُرجع أرباح الشهر الحالي والشهر الماضي مع نسبة النمو — مثال: {"this_month": 85000, "last_month": 70000, "growth": 21.4}. النسبة يمكن أن تكون سالبة في حال تراجع الأرباح.
لا يحتاج body

الإشعارات

Notifications
GET /vendor/notifications 🔒 Token
يُرجع قائمة إشعارات الـ vendor مرتبةً من الأحدث — يشمل unread_count لعرض الرقم على أيقونة الجرس (badge).
لا يحتاج body
POST /vendor/notifications/{id}/read 🔒 Token
يُعلّم إشعاراً واحداً كمقروء (read_at = now()) — يُستدعى عند الضغط على إشعار محدد.
لا يحتاج body
POST /vendor/notifications/read-all 🔒 Token
يُعلّم جميع الإشعارات غير المقروءة كمقروءة دفعةً واحدة — يُستخدم عند فتح شاشة الإشعارات لتصفير البادج.
لا يحتاج body
